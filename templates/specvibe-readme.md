# SpecVibe

> This directory is the source of truth for AI-assisted development in this repository.

## What lives here

| Path | Purpose |
| --- | --- |
| `constitution.md` | Non-negotiable architecture rules, limits, and quality gates. |
| `context.md` | Product intent, users, conventions, and current focus. |
| `decisions.md` | Append-only architectural decision log. |
| `context/codebase-summary.md` | Compressed codebase map generated by `specvibe scan`. |
| `context/scan.json` | Machine-readable scan index used by `specvibe pack`. |
| `tracks/<slug>/` | Active feature plans: proposal, spec, design, tasks, metadata. |
| `archive/` | Completed or reverted tracks, preserved for history. |
| `packs/` | Token-optimized context packs (local, gitignored). |

## The loop

1. `specvibe scan` — understand the existing code before planning.
2. `specvibe propose "<feature>"` — create a track. No code yet.
3. `specvibe approve <track>` — after a human approves the plan.
4. `specvibe apply <track>` — creates a git checkpoint and starts the task loop.
5. `specvibe unify <track>` — verifies acceptance criteria, archives, and logs decisions.

Agents use the same commands through their native slash commands (`/sv:propose`, `/sv:apply`, `/sv:unify`, and agent-specific variants).

## Commit this directory

Commit `constitution.md`, `context.md`, `decisions.md`, `context/`, `tracks/`, and `archive/`. Keep `packs/`, `backups/`, and `tmp/` local; this directory's `.gitignore` handles that.

Do not edit `archive/` or generated agent instruction files by hand. Edit the constitution/context and run `specvibe agents sync`.
