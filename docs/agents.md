# Agent integrations

SpecVibe keeps the workflow in one place — `.specvibe/` and the CLI — and generates the small native files each AI host expects.

Nothing important is duplicated. Generated instruction files contain a short workflow block and point agents at the constitution, context, and active track. Native command files call the CLI and repeat the non-negotiables.

## Supported agents

| Agent ID | Detection markers | Instruction files | Native commands |
| --- | --- | --- | --- |
| `opencode` | `.opencode/`, `opencode.json`, `opencode.jsonc` | `AGENTS.md` | `.opencode/commands/sv/<name>.md` |
| `claude` | `.claude/`, `CLAUDE.md` | `CLAUDE.md`, `AGENTS.md` | `.claude/commands/sv/<name>.md` |
| `cursor` | `.cursor/`, `.cursorrules` | `.cursor/rules/specvibe.mdc`, `.cursorrules`, `AGENTS.md` | `.cursor/skills/sv-<name>/SKILL.md` |
| `gemini` | `.gemini/`, `GEMINI.md` | `GEMINI.md`, `AGENTS.md` | `.gemini/commands/sv/<name>.toml` |
| `windsurf` | `.windsurf/`, `.windsurfrules`, `.devin/` | `.windsurf/rules/specvibe.md` or `.devin/rules/specvibe.md`, `AGENTS.md` | `.windsurf/workflows/sv-<name>.md` or `.devin/workflows/sv-<name>.md` |
| `copilot` | `.github/copilot-instructions.md`, `.github/prompts/`, `.github/instructions/` | `.github/copilot-instructions.md`, `AGENTS.md` | `.github/prompts/sv-<name>.prompt.md` |
| `generic` | `AGENTS.md` | `AGENTS.md` | — |

If `.devin/` exists, Windsurf files are written there instead of `.windsurf/`, matching the Devin Desktop layout. Detection checks all markers and reports every match.

When you run `init` without `--agents`, SpecVibe uses the detected agents. If nothing is detected, it configures `generic`. If you pass `--agents none`, it writes only the `.specvibe/` baseline.

## Generated commands

The same nine commands are generated for every host that supports native commands:

`setup`, `scan`, `propose`, `plan`, `apply`, `unify`, `pack`, `status`, `revert`

| Command | What the agent should do |
| --- | --- |
| `setup` | Refine the constitution and project context with the user. |
| `scan` | Run or interpret a repository scan; reuse existing code. |
| `propose` / `plan` | Create a track. No implementation code. Ask the human to fill gaps and approve. |
| `apply` | Work one task at a time, stop at gates, report evidence. |
| `unify` | Verify acceptance criteria, archive the track, record decisions. |
| `pack` | Produce a token-budgeted context pack for the current track. |
| `status` | Read progress and the next safe action. |
| `revert` | Preview a rollback. Never execute `--yes` without explicit consent. |

Argument placeholders are host-specific:

| Host | Placeholder |
| --- | --- |
| OpenCode, Claude Code | `$ARGUMENTS` |
| Gemini CLI | `{{args}}` |
| Copilot | `${input:feature:Describe the feature you want to plan}` |
| Cursor, Windsurf | Natural-language instruction in the skill/workflow |
| Generic | CLI examples |

## Invoking commands

| Agent | Example |
| --- | --- |
| OpenCode | `/sv/propose Add CSV export` |
| Claude Code | `/sv:propose Add CSV export` |
| Gemini CLI | `/sv:propose Add CSV export` |
| Cursor | Ask for the `sv-propose` skill, or use the command palette |
| Windsurf | `/sv-propose Add CSV export` |
| Copilot | Select the `sv-propose` prompt in Copilot Chat |
| Any host | `specvibe propose "Add CSV export"` |

Command availability depends on the host version and how it discovers project files. The CLI is always the fallback.

## Managed files vs owned files

SpecVibe writes two kinds of files:

### Managed

Managed files may contain user content and a SpecVibe block:

```markdown
Your existing instructions...

<!-- specvibe:start -->
<!-- Managed by SpecVibe. Edit .specvibe/constitution.md and .specvibe/context.md... -->
...
<!-- specvibe:end -->

More of your content...
```

On sync, only the block is replaced. Everything outside the markers is preserved. If the markers are incomplete (only a start or only an end), SpecVibe skips the file and warns instead of guessing.

Managed files include:

- `AGENTS.md`
- `CLAUDE.md`
- `GEMINI.md`
- `.github/copilot-instructions.md`
- `.cursorrules`

### Owned

Owned files are fully generated and contain:

```text
<!-- specvibe:generated file: run `specvibe agents sync` to refresh -->
```

On sync:

- If the file is missing, it is created.
- If it was generated by SpecVibe, it is updated.
- If it exists but was not generated by SpecVibe, it is skipped and a warning is printed.
- With `--force`, the existing file is backed up under `.specvibe/backups/<timestamp>/` and replaced.

Owned files include native command files and Cursor/Windsurf rule files.

On removal:

- Generated owned files are deleted.
- Non-generated owned files are left untouched with a warning.
- Managed blocks are stripped; the file is deleted only if nothing else remains.

## Managing integrations

```bash
specvibe agents list
specvibe agents detect
specvibe agents add opencode,claude
specvibe agents remove cursor
specvibe agents sync
specvibe agents sync --force
```

`agents add` and `agents remove` update the configured list and the generated files. `agents sync` regenerates files for the current configuration.

Changing the agent list with `specvibe config set agents ...` updates only `config.json`; run `specvibe agents sync` afterward.

## What agents are told

Generated instructions include the following rules, adapted from `templates/agents/rules.md`:

1. **Read context in order:** constitution → context → codebase map → active track.
2. **No feature code before approval.** Planning and documentation only.
3. **Reuse before create.** Search for existing components, helpers, types, and patterns; cite them in the design.
4. **Respect size limits.** Files and functions above the configured limits must be extracted rather than extended.
5. **One task at a time.** Do not skip ahead or batch unrelated changes.
6. **Gates require evidence.** Run the command, report the result, and wait for the user.
7. **No bypass flags without consent.** `--force`, `--allow-dirty`, `--allow-no-git`, and `revert --yes` require explicit agreement.
8. **Do not edit** archives, `scan.json`, or generated agent files; regenerate them with the CLI.
9. **Stop and ask** when requirements are ambiguous, a test fails, or the plan no longer fits.
10. **Do not commit** unless the user asks.

SpecVibe cannot sandbox an agent. Use your host's permission system, review diffs, and keep the constitution short enough that it is actually read.

## Context discipline

Every host has a finite context window. Generated instructions tell agents to:

- load only files relevant to the current task
- use `specvibe pack <track>` for a new session or a large repository
- treat the constitution and approved spec as authoritative
- never paste secrets, `.env` files, or large generated artifacts

A pack lists what was included, truncated, and omitted, so the agent knows the limits of its context.

## Repository files to commit

Commit:

- `.specvibe/constitution.md`
- `.specvibe/context.md`
- `.specvibe/decisions.md`
- `.specvibe/config.json`, `state.json`
- `.specvibe/context/`
- `.specvibe/tracks/`
- `.specvibe/archive/`
- `AGENTS.md` and other generated instruction files
- native command folders

Do not commit:

- `.specvibe/packs/`
- `.specvibe/backups/`
- `.specvibe/tmp/`

`.specvibe/.gitignore` handles the local-only folders. The scanner also ignores them.
